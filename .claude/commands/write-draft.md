# 記事執筆スキル: write-draft

このスキルは、テーマを受け取り、リサーチから下書き作成までを自動化します。

## 実行手順

### 1. テーマの確認
- ユーザーから記事テーマを受け取る
- 曖昧な場合は以下を確認：
  - ターゲット読者は誰か
  - 記事の目的（情報提供、意見表明、SEO対策など）
  - 希望する文字数（デフォルト: 2000-3000字）
  - トーン（専門的、カジュアル、ビジネスライクなど）

### 2. リサーチフェーズ
以下の3つのリサーチを並行実行：

#### 2-1. 思考分析リサーチ
- テーゼ（主張）・アンチテーゼ（反論）・ジンテーゼ（統合）の論考分析
- 多角的な視点から問いを立てる
- 深い洞察を引き出す

#### 2-2. 事実ベースリサーチ
- Web検索で最新情報を収集
- 統計データ、事例、専門家の見解を調査
- 出典を明記

#### 2-3. 批判的リサーチ
- Devil's Advocate的な視点
- よくある誤解や偏見を指摘
- 弱点や反論可能性を検討

### 3. 構成設計
リサーチ結果を統合し、記事の構成案を作成：
- タイトル候補（3パターン）
- リード文
- 見出し構成（H2, H3レベル）
- 各セクションの要点
- 結論・まとめの方向性

**構成案をユーザーに提示し、承認を得る**

### 4. 下書き執筆
承認された構成案に基づいて執筆：
- 論理的な流れを重視
- 具体例・データを適切に配置
- 読みやすい文章構造
- SEOを意識したキーワード配置（自然な範囲で）

### 5. 品質チェック
以下の4軸で自己レビュー：
1. **洞察の深さ**: ありふれた内容ではなく、独自の視点があるか
2. **論理の明快さ**: 主張が明確で、根拠が適切か
3. **So Whatの強さ**: 読者にとっての価値・学びが明確か
4. **構成の完成度**: 全体の流れが自然で、読みやすいか

問題があれば修正する。

### 6. 出力
以下の形式で `output/articles/` に保存：

```
output/articles/YYYY-MM-DD_[記事タイトル].md
```

ファイル内容：
```markdown
---
title: [記事タイトル]
date: YYYY-MM-DD
status: draft
target_audience: [ターゲット読者]
keywords: [キーワード1, キーワード2, ...]
word_count: [文字数]
---

# [記事タイトル]

[記事本文]

---

## メタ情報

### 参考文献
- [出典1]
- [出典2]

### 執筆メモ
- [構成のポイント、注意事項など]
```

### 7. 次のアクションを提案
- タイトルの改善案
- 追加すべき情報
- 画像・図表の挿入位置
- 公開前のチェックポイント

## 注意事項

### 機密情報
- 顧客情報、クライアント名は記載しない
- 不確実な情報は必ず確認を取る

### コンテンツ品質
- **質>量**: 浅い記事よりも深い洞察
- **独自性**: ありふれた内容は避ける
- **検証**: 事実は必ず出典を確認
- **構造化**: 論理的で読みやすい構成

### ユーザーとの対話
- 推測で進めず、不明点は確認
- 構成案は必ずユーザーに承認を得る
- 修正要望には柔軟に対応

## 使用例

**ユーザー**: 「AIと人間の協働について記事を書いて」

**Claude**:
1. テーマ確認（ターゲット読者、文字数など）
2. 3方向のリサーチを実行
3. 構成案を提示し、承認を得る
4. 下書きを執筆
5. 品質チェック
6. `output/articles/2026-02-13_AI人間協働の未来.md` に保存
7. 次のアクション提案
