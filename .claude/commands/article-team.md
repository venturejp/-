# 記事執筆エージェントチーム

6人のAIエージェントが協働して、高品質な記事を制作します。

## チーム構成

```
[テーマ入力]
    ↓
[リサーチフェーズ（並列実行）]
├─ リサーチャーA（思考分析）
├─ リサーチャーB（事実ベース）
└─ リサーチャーC（批判的思考）
    ↓
[構成エージェント]
    ↓
[編集長]（構成案レビュー）
    ↓
[ライター]
    ↓
[編集長]（最終レビュー）
    ↓
[完成記事]
```

## 実行手順

### ステップ1: テーマと要件の確認
ユーザーからテーマを受け取り、以下を確認：
- ターゲット読者
- 希望文字数（デフォルト: 2000-3000字）
- トーン（専門的、カジュアル、ビジネスライクなど）
- 特別な要望

### ステップ2: リサーチフェーズ（並列実行）

以下の3つのリサーチを**並列で実行**：

#### リサーチャーA - 思考分析
`.claude/agents/article-team/researcher-a-dialectics.md` の指示に従う：
1. テーゼ（主張）の設定
2. アンチテーゼ（反論）の検討
3. ジンテーゼ（統合）の提示

#### リサーチャーB - 事実ベース
`.claude/agents/article-team/researcher-b-facts.md` の指示に従う：
1. 統計データの収集
2. 事例の調査
3. 専門家・有識者の見解
4. 最新情報の確認

#### リサーチャーC - 批判的思考
`.claude/agents/article-team/researcher-c-critical.md` の指示に従う：
1. よくある誤解の指摘
2. 主張の弱点分析
3. リスクと課題の洗い出し
4. 反論可能性の検討

### ステップ3: 構成設計
`.claude/agents/article-team/structure-designer.md` の指示に従う：
1. 3つのリサーチレポートを統合
2. 記事の方向性決定
3. タイトル案の作成（3パターン）
4. リード文の作成
5. 見出し構成の設計
6. 各セクションの要点整理

**出力**: 構成案をユーザーに提示

### ステップ4: 構成案レビュー（編集長）
`.claude/agents/article-team/editor-in-chief.md` の指示に従う：
1. 洞察の深さを評価
2. 論理の明快さを評価
3. So Whatの強さを評価
4. 構成の完成度を評価

**出力**:
- 各軸の評価（5段階）
- 具体的なフィードバック
- 修正が必要な場合は、構成エージェントに戻る

**ユーザーに構成案の承認を求める**

### ステップ5: 執筆（ライター）
`.claude/agents/article-team/writer.md` の指示に従う：
1. 構成案の理解
2. 執筆準備
3. 執筆実行（導入→本論→結論）
4. 文章品質の確保
5. 自己チェック

**出力**: 下書き原稿

### ステップ6: 最終レビュー（編集長）
`.claude/agents/article-team/editor-in-chief.md` の指示に従う：
- 4軸で再評価
- 修正が必要な場合は、ライターに戻る
- 完成と判断したら次へ

### ステップ7: 保存と次のアクション
1. `output/articles/YYYY-MM-DD_[記事タイトル].md` に保存
2. ユーザーに完成を報告
3. 次のアクション提案：
   - タイトルの改善案
   - 追加すべき情報
   - 画像・図表の挿入位置
   - 公開前のチェックポイント

## 品質保証

### 4つの評価軸
1. **洞察の深さ**: 独自の視点、深い洞察
2. **論理の明快さ**: 明確な主張、適切な根拠
3. **So Whatの強さ**: 読者にとっての価値
4. **構成の完成度**: 自然な流れ、読みやすさ

### レビュー回数
- 構成案レビュー: 1回（編集長）
- 最終原稿レビュー: 1回（編集長）
- 必要に応じて追加レビュー

## 使用例

**ユーザー**: 「AIと人間の協働について記事執筆チームで記事を書いて」

**実行フロー**:
1. テーマ確認（ターゲット読者、文字数など）
2. リサーチャー3人が並列でリサーチ
3. 構成エージェントが構成案を作成
4. 編集長が構成案をレビュー
5. ユーザーが構成案を承認
6. ライターが執筆
7. 編集長が最終レビュー
8. `output/articles/2026-02-13_AI人間協働の未来.md` に保存

## 注意事項

### 機密情報
- 顧客情報、クライアント名は記載しない
- 不確実な情報は記載しない

### ユーザーとの対話
- 推測で進めない
- 構成案は必ずユーザーに承認を得る
- 不明点は確認する

### 品質基準
- 質>量
- 独自性を重視
- 事実は必ず出典を確認
- 読者ファースト
