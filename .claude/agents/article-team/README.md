# 記事執筆エージェントチーム

複数のAIエージェントが協働して、高品質な記事を制作するチームシステムです。

## チーム構成

```
[テーマ入力]
    ↓
[リサーチフェーズ（並列実行）]
├─ リサーチャーA（思考分析）
├─ リサーチャーB（事実ベース）
└─ リサーチャーC（批判的思考）
    ↓
[構成エージェント]（3つのリサーチを統合）
    ↓
[編集長]（構成案レビュー）
    ↓
[ライター]（原稿執筆）
    ↓
[編集長]（最終レビュー）
    ↓
[完成記事]
```

## エージェント詳細

### 1. リサーチャーA - 思考分析担当
- **役割**: テーゼ・アンチテーゼ・ジンテーゼの論考分析
- **ファイル**: `researcher-a-dialectics.md`
- **得意分野**: 多角的な視点、深い洞察、論理的思考

### 2. リサーチャーB - 事実ベース担当
- **役割**: 技術・産業の事実に基づく調査
- **ファイル**: `researcher-b-facts.md`
- **得意分野**: データ収集、統計分析、事例研究

### 3. リサーチャーC - 批判的思考担当
- **役割**: Devil's Advocate（悪魔の代弁者）
- **ファイル**: `researcher-c-critical.md`
- **得意分野**: 反論、弱点指摘、リスク分析

### 4. 構成エージェント
- **役割**: 3つのリサーチを統合し、記事構成を設計
- **ファイル**: `structure-designer.md`
- **得意分野**: 情報整理、論理構成、ストーリー設計

### 5. 編集長
- **役割**: 品質チェックとフィードバック
- **ファイル**: `editor-in-chief.md`
- **評価軸**:
  1. 洞察の深さ
  2. 論理の明快さ
  3. So Whatの強さ
  4. 構成の完成度

### 6. ライター
- **役割**: 編集長のフィードバックを反映した原稿執筆
- **ファイル**: `writer.md`
- **得意分野**: 文章表現、読みやすさ、SEO最適化

## 使用方法

### 基本的な使い方
```
「[テーマ]について記事執筆チームで記事を作って」
```

### 詳細指定
```
「[テーマ]について記事執筆チームで記事を作って。
- ターゲット: [読者層]
- 文字数: [文字数]
- トーン: [専門的/カジュアルなど]
```

## 品質保証

### 4つの評価軸
1. **洞察の深さ**: ありふれた内容ではなく、独自の視点があるか
2. **論理の明快さ**: 主張が明確で、根拠が適切か
3. **So Whatの強さ**: 読者にとっての価値・学びが明確か
4. **構成の完成度**: 全体の流れが自然で、読みやすいか

### レビュー回数
- 構成案レビュー: 1回
- 最終原稿レビュー: 1回
- 必要に応じて追加レビュー

## 出力形式

完成記事は以下の形式で保存されます：
```
output/articles/YYYY-MM-DD_[記事タイトル].md
```

## カスタマイズ

### エージェントの追加
新しいリサーチャーや専門家エージェントを追加できます。

### ワークフローの変更
チーム構成やレビュー回数を調整できます。
